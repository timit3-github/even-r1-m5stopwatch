# 省電力動作と確認結果

v0.3.1はリリース前の長時間試験で使った省電力構成（旧MODE3）を通常動作として採用しています。
検証モードの切り替えと検証履歴の収集は削除し、動作設定・VIN取得周期は維持しています。
省電力構成の実機結果は以下のとおりです。検証用コードを整理したv0.3.1そのものの実機確認は未実施です。

## 動作

- CPUはDFSで40～160MHz、Bluetooth Modem-sleepと自動Light-sleepを使用します。
- BLE待機時の時刻基準は主40MHz水晶です。通信に必要な起床はESP-IDFが制御します。
- 無操作60秒で操作待機へ移行し、タッチのI2C取得を停止します。
- 手動でタッチを無効にした場合もI2C取得を停止します。ボタン復帰で手動設定は変更しません。
- 操作待機からの復帰はG1/G2ボタンです。最初の押下も操作として判定します。
- 待機中のタッチは復帰に使いません。復帰時に触れていた指は、一度離してから操作してください。
- 接触中、ボタン保持中、タップ判定待ち、送信待ちは待機移行を保留します。
- 待機中のホスト周期処理は1秒、バッテリー電圧取得は30秒です。通常時の電圧取得は1秒です。
- VINは待機中も1秒周期で取得します。G2/iPhoneからの要求や送信待ちは周期処理を待たずに処理します。
- Deep-sleep、手動Light-sleep、BLE停止は使いません。NVSのbond情報と既存GATT配置を維持します。

タッチ取得の停止はCST820Bの電源遮断ではありません。周辺回路の消費電力は残ります。
両ボタンを未使用に設定した場合は、ボタン復帰ができないため操作待機への移行を無効にします。

## USB接続中のLight-sleep抑止

StopWatchのPM1からVINを取得し、4000mV以上でusb_vinのNO_LIGHT_SLEEPロックを保持します。
3000mV以下の読み取りを繰り返し、最初の低電圧サンプルから2000ms以上経過したら解除します。
その間の読み取り失敗、6500mVを超える異常値、閾値外のサンプルは解除確認を取り消します。
読み取り失敗時は最後の検出状態とロックを保持します。失敗が続く場合は省電力へ戻れない可能性があります。

USB充電器だけの接続でもロックを保持します。USB抜去後は解除し、再接続時は再取得します。
再接続の検出には最大約1秒とI2C処理時間がかかります。標準USB接続監視のロックも有効です。
PM1の電源・充電設定は書き換えません。閾値と周期はinclude/r1_config.hで変更できます。

## 作者実機の結果

環境はM5Stack StopWatch、ESP-IDF 5.5.1、Evenアプリ2.3.2、G2 2.3.2.14です。
USB未接続のバッテリー駆動で、無操作60秒後のタッチ停止、ボタンによる操作再開、
待機からの最初の二度押しを確認しました。
USB接続中の10分以上の待機で自然切断がなく、抜去後のロック解除・Light-sleep、再接続後の再取得を確認しました。
USB接続中のVINは約4.9～5.0V、抜去中は0Vでした。

長時間試験はアプリの低電力モードOFF、G2を途中で充電しない条件で実施しました。
開始・終了のuptime_msは1406627から77328942へ継続し、差は約21時間5分22秒でした。
開始・終了時のUSB接続での取得時間も含む区間であり、USB未接続時間の秒単位の測定値ではありません。

| 項目 | 開始 | 終了 |
|---|---:|---:|
| G2切断 | 0 | 0 |
| 全リンク切断 | 0 | 4 |
| NimBLEホストリセット | 0 | 0 |
| 待機移行 / 復帰 | 2 / 2 | 9 / 8 |
| Light-sleep回数 | 157 | 2797111 |
| Light-sleep累積時間 | 約1.907秒 | 約54611.928秒 |

試験区間のLight-sleep滞在率は約71.9％でした。終了時も再接続操作なしでボタン・タッチからG2を操作できました。
全リンク切断4回の相手・理由はstatusだけでは特定できません。スマホ接続の連続維持は確認していません。
待機復帰が6回増えているため、完全無操作の試験とは区別します。
開始時の推定残量は90％、途中20時間49分時点のEvenアプリ表示は19％、USB再接続後の推定残量は24％でした。
電圧推定であり、平均電流や残り稼働時間には換算しません。長期安定性は未確認です。
Evenアプリの残量表示と、G2ダッシュボードの電池アイコンが残量に応じて変わることを確認しました。
この実機構成のR1_APP_VERSIONは2.9.9.9999で、v0.3.1の既定値も同じです。プロジェクト版とは別の通知文字列です。

## 診断

ビルドは[BUILD.md](BUILD.md)を参照してください。起動時にFIRMWARE_VERSION=0.3.2、
POWER_CONFIGのdfs=40..160MHzとauto_light_sleep=1を確認します。
statusまたはpmを入力してEnterを押すと、uptime、待機状態、接続・切断数、バッテリー・タッチ・VIN状態を取得できます。
pmは電源管理ロックと滞在時間も表示します。state=waitingは操作待機で、CPUがその瞬間にLight-sleep中という意味ではありません。
USB接続中にusb_vinがActive=1となるのは正常です。待機中のTOUCH_PANEL valid=0も取得停止による正常な状態です。
接続中の診断ではLight-sleepが抑止されます。バッテリー試験はUSBを外して行ってください。
ログには実機アドレスが含まれるため、公開時は伏せてください。
